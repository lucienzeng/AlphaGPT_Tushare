| 阶段 | 改造内容 |
| --- | --- |

| 研究管理 | 冻结研究计划；相同计划跨任务累计候选预算；同计划模型候选、基线、模板及固定种子随机对照一起做训练区去重 |
| 候选评价 | 区分可计算、开发筛选通过、独立检验初筛通过；增加时间分段IC、方向一致性与区块自助诊断，不将初筛当盈利保证 |
| 界面与安全边界 | 窗口最小值统一为20；已观察区间跨快照标记重测；坏快照友好拦截；回测直接拒绝空涨跌停价，避免NaN绕过约束 |

新任务采用 `isolated-v1`，旧配置缺少协议字段时按 `legacy-v1` 解释，旧结果不被改写。模型输出仍使用历史窗口标准化转换为仓位，因子原始正收益不等于最终一定做多。

## 使用方式

- **数据同步 → 数据质量、可用时间与官方对账**：检查快照，查看质量记录或导入已统一单位的官方CSV。字段为 `ts_code,trade_date` 和待比较的 `open,high,low,close,settle,vol,oi,amount`；日期为 `YYYY-MM-DD`。
- **因子挖掘 → 研究计划与对照预算**：默认累计30个模型候选，另配置随机合法对照。相同完整配置自动关联同一计划；改变研究假设会生成新计划，但不能清除已观察日期。
- **因子列表**：查看研究阶段、研究计划和独立验证标记。无合格模型候选时任务可以正常结束，保留淘汰原因，不降低门槛凑数量。
- DBeaver可查看 `期货_质量检查`、`期货_来源版本`、`研究_区间暴露`；底层记录保存在SQLite的 `objects` 表。

## 发现的真实数据问题与边界

**2025—2026旧快照存在必须处理的来源缺口：2026-01-30有10个合约的涨跌停价格为空，包括主力CU2603.SHF。** 单次Tushare复查仍为空，记录见 `runtime/verification/limit_source_probe.json`，对应完整JSONL日志以其中任务编号定位。新质量校验会拦截该快照的研究使用，直接回测也不会允许空值绕过涨跌停判断。

这是来源缺口，并未伪造修复。需取得可信来源补充参数，再经正常入库生成新快照；旧快照保持原样。2024通过校验的快照可正常运行。

本轮交付官方对账导入能力及其测试，**尚未实际取得并完成30～50个官方交易日的独立对账**。历史精确发布时间和夜盘开盘口径仍待来源核实。更早历史、完整期限曲线及库存接入按方案后续阶段推进；本轮没有批量扩大下载或新增因子信息源。时间分段诊断也不等同于自动嵌套滚动重挖流程。
