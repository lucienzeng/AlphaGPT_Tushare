# 沪铜期货因子挖掘项目：可行性评估与改进方案

评估日期：2026-10-19，北京时间。评估对象：本地 `AlphaGPT_Tushare` 当前工作区，而非仅 Git 已提交版本。

本文只提出方案。本次进行了代码阅读、SQLite 只读查询、既有验收记录核对和两个内存级边界验证；未修改功能代码、配置或业务数据，未调用模型、下载新行情或解封测试集。既有“51项测试通过”来自上一轮验收记录，本次未重新运行整套测试。文中的工作量、预算及准入阈值均为建议，尚未实施。

## 1. 结论：值得继续，但下一阶段应优先提高研究可信度

**项目适合作为个人沪铜日频量化研究工作台，工程闭环已经成立；目前还不足以证明能稳定挖掘出可实盘盈利的因子。** 建议继续沿用现有技术栈，先补齐数据时点、研究隔离、执行假设和稳健性评价，再扩展期货专属数据。暂不引入 OpenBB、分布式服务或新的数据库。

真正的瓶颈不是模型不够强，而是：单品种日频样本有限、量价特征高度同质、验证集会被反复优化、日线成交近似，以及历史数据发布时间和修订版本尚未完整留存。增加轮次只能增加搜索量，不能自动增加有效信息。

| 使用目标 | 当前可行性 | 判断依据与边界 |
| --- | --- | --- |
| 学习、核对数据、验证因子假设 | 高 | 已有同步、冻结快照、曲线选择、模型生成、真实月合约回测、界面和日志 |
| 有约束地筛选日频候选 | 有条件可行 | 需要更多历史、滚动检验、试验登记和成本压力测试 |
| 证明模型组合优于简单规则 | 尚未证明 | 缺少与固定模板、随机合法搜索在同预算下的独立对照 |
| 将某个漂亮回测直接用于实盘 | 当前依据不足 | 未完成成交时点审计、独立确认和前向模拟交易 |
| 高频或盘口策略 | 当前不适合 | 现有数据粒度和撮合模型定位于日频研究 |

本项目更准确的定位是“**受约束的因子假设生成与验证系统**”。模型负责提出公式和解释，数学计算、可用时间、交易规则和是否准入由确定性程序负责。经济解释只是待验证的假设。

## 3. 已有优点及需要保留的设计

1. **信号价格和成交价格分离。** 复权主连只用于研究；实际月合约原价用于成交、换月与结算。避免将主连拼接跳空直接计为收益。
2. **因果复权与历史窗口。** 换月系数使用上一交易日新旧合约价格，特征标准化基准滞后，已有前缀一致性和未来扰动测试。
3. **表达式执行受约束。** 模型只能使用指定特征和算子；禁止属性、下标、任意代码、时间位移和标签访问。比直接执行模型生成的 Python 更适合个人研究系统。
4. **下载有实际工程保障。** 分接口限流、重试、行数上限拆分、覆盖记录、缺口留存、增量同步和单执行器已实现；不需重新建设一套数据平台。
5. **研究过程可追踪。** 快照、曲线、实验配置、模型响应、用量、源码摘要、账本及 JSONL 日志都有保存。
6. **期货适配已有基础。** 月合约内计算量持仓变化，考虑交割保护、涨跌停拒单、保证金预算、手续费、滑点和换月费用。
7. **适合个人维护。** SQLite、Parquet、Pandas、Streamlit 足以承担当前规模；单机排查与备份成本可控。

这些是值得延续的资产。改进应围绕三层展开：数据处理、因子研究、交易回测；日志和界面作为公共能力，不必拆成大量服务。

### 4.1 一个容易忽略的研究语义问题

新版加入原始收益特征是正确方向，但不意味着原始正收益就会做多。当前仓位逻辑仍是：

```text
公式输出 → 相对自身历史均值的标准分 → 阈值 → 多/空/空仓
```

例如近期收益始终为正，但今天从5%下降到1%，标准化后可能产生空头。这是“相对强弱”策略，不能解释成“收益为正就顺势做多”。同样，`is_roll` 或 `days_to_last_trade` 单独进入公式，可能变成自动预测多空的方向信号。

建议新增明确的 `signal_policy`：保留旧版 `rolling_zscore`；另加原始方向策略及“方向×非负强度”策略。生命周期默认用于禁入、降仓和诊断，不直接提供多空方向。每个策略版本要写清因子值到仓位的完整转换，不能只解释公式。

## 5. 数据可靠性与无未来数据方案

### 5.1 第一优先：建立信息可用时间，而不只是交易日期

为数据记录或批次增加下列元数据；供应商没有给出的时间应为空或标记估计，不能把下载时间伪装成历史发布时间。

| 字段 | 作用 |
| --- | --- |
| `trade_date` / `observation_date` | 数据归属的交易日或观察期 |
| `published_at` | 可核实的首次发布时间 |
| `available_at` | 系统允许用于决策的最早时间，包含可验证的保守延迟 |
| `effective_from` / `effective_to` | 费率、保证金、交易限制适用区间 |
| `fetched_at` | 本次获取时间，与发布时间分开 |
| `source_revision` / `content_hash` | 来源修订标识与内容校验 |
| `availability_status` | 已核实、保守假设、未知 |

时点读取只能返回 `available_at <= decision_time` 的版本；后来的修订不能覆盖当时可见值。历史无版本数据需标记“回溯重建”，与从现在起逐日保存的真实版本区分。

上期所夜盘存在跨自然日的交易安排，不能把 `trade_date` 直接当日历日开盘时间。应结合交易所时段、节假日夜盘安排及供应商样本确认 `fut_daily.open` 对应哪一次开盘。Tushare日线文档仅列出“开盘价”字段，不能据此推定是日盘09:00。[上期所交易时间](https://www.shfe.com.cn/services/calenderandholidays/tradinghours/)、[Tushare期货日线](https://tushare.pro/document/2?doc_id=138)。

### 5.2 合约选择与复权处理

继续保留当前因果比例复权：

```text
换月日t：调整系数(t) = 调整系数(t-1) × 旧合约收盘(t-1) / 新合约收盘(t-1)
信号OHLC(t) = 新合约原始OHLC(t) × 调整系数(t)
```

不改用依赖样本终点、会重写历史的复权来替代它。成交、手续费和保证金继续使用月合约原价，量和持仓不随价格系数复权。

但需要明确：**复权公式因果，不等于主力映射已证明点时可得。** Tushare提供每日主连与月合约映射，公开接口字段本身没有完整的历史发布及修订轨迹。[Tushare主力与连续合约](https://tushare.pro/document/2?doc_id=189)。

建议研究曲线分三个用途：

- 因果复权主连：作为主要价格趋势与反转研究序列。
- 真实月合约：用于核对、生命周期分层、同合约检验，不能只挑回测表现好的月份。
- 原始主连：保留换月污染对照标签，不参与默认排行榜。

下一步可新增透明选约规则作为稳健性对照：在决策时已上市且未进入交割保护的完整合约池中，用已可得的持仓/成交数据选约；预先固定确认天数、流动性门槛和换月条件。不能从“事后成为过主力”的合约集合挑选。该规则与Tushare映射并行保存，禁止看完收益后挑表现最佳的映射。

### 5.3 交叉校验分为四层

1. **基础结构检查**：键唯一、日期有效、OHLC关系、必要数值有限、成交量/持仓非负、单位一致。真实零成交与缺行情不同；不能用填0消除缺失。
2. **跨表核对**：映射有对应行情；执行月合约有有效乘数、涨跌停与保证金；换月前日有新旧价格；持仓持续期间行情完整；费用缺口按费率模式判断是否阻断。
3. **独立来源对账**：先人工下载/导入上期所官方历史日行情文件，建立小型对账器。优先覆盖换月、极端价格、节前后、交割附近和随机普通日，示例首批30～50个交易日。价格字段原则上匹配来源精度；任何容差须显式定义，1个最小变动价位差异也不能默认忽略。量、金额和持仓先统一单双边及历史单位。
4. **修订监控**：对最近若干已完成交易日定期复查；旧值和新值生成差异记录及新快照，不覆盖既有实验。两个第三方若转引同一源，不能当两份独立证据。

建议 `quality_checks` 保存规则、对象、等级、实测/期望值、来源、任务和处理状态；`data_gaps` 继续保存缺口。先用SQLite和导入文件完成，不必上线第二套常驻行情平台。

验收要求：用于该实验的关键数据问题全部明确；未解决的价格/映射/持仓连续性问题阻断执行；缺可选数据只禁用相关特征；历史费率缺失禁止该成本模式。可用率99%不能代替对关键1%缺口的处理。

### 5.4 无未来数据的测试边界

已有AST白名单、前缀一致性、未来行情扰动、盘后字段不影响当日开盘订单等检查应保留，并增加：

- 模拟主力映射次日发布、后来修订，确认早期订单不变化。
- 模拟节假日夜盘及费率/保证金生效时间，确认决策只能看到当时版本。
- 同一公式在逐日回放和批量计算下逐值一致。
- 将未解封测试文件移除或拒绝访问，开发仍能运行；当前开发计算前会截断，但 `load_snapshot()` 仍先加载整份文件，属于逻辑隔离，尚非文件访问级隔离。
- 滚动分段的标签信息区间不得跨越选择边界；所有外层表现均不得进入更早时点的生成过程。
- 用反例固定订单时序：预提交订单不能依赖尚未形成的最终开盘价、收盘或结算结果。

离线评价标签可以使用事后价格；禁止的是将这些结果用于当时特征、选约、下单或此前的候选选择。不能为了“禁未来”删掉用于检验的真实标签。

## 6. 因子研究与防过拟合方案

### 6.1 将研究划分为计划、开发、独立检验三个层次

每轮研究先冻结 `research_plan_id`，至少包含：历史区间、特征版本、选约和复权方法、信号转换、标签周期、费用、模型及提示词版本、搜索预算、选择规则、候选上限和保留区间。

当前反馈模型的“验证集”应视作开发数据。建议采用按时间前推的嵌套流程：

1. 在每个外层截点之前，用内层训练与验证生成、筛选并冻结候选。
2. 外层下一段只评估已冻结候选，不把该段结果用于同一段重新选择。
3. 时间推进后，可把已经结束的外层段纳入下一次开发；新候选只能从下一未发生区间开始计入前向表现。
4. 保存每个截点实际选中了哪些因子，拼接的是“当时能选出的策略”净值，而不是事后在全部折上选择赢家再称其样本外。
5. 单独保留一个最终锁箱区间。解封后该区间永久成为已观察数据，修改公式或参数不能重置独立性。

`test_access` 应升级为研究计划及底层品种/时间区间的暴露记录。修复数据生成新快照、克隆任务或换模型，不能恢复同一时间段的“未看过”状态。允许重复执行用于复核，但显示为已暴露重测。

### 6.2 历史数据与日期建议

建议先补充约2015—2023年的铜日线及必要映射、元数据与执行参数，用于增加制度和行情状态覆盖；开始日以接口实际完整性核验为准。跨2020的数据口径与预热分段要继续保留。多年历史只是增加检验机会，不能保证当年的统计关系适用于今天。

在本项目现状下建议这样定位各区间：

| 区间 | 建议用途 |
| --- | --- |
| 2015—2023，补齐后 | 构造多个历史前推实验；不是天然独立锁箱，因为研究者已知重大历史事件 |
| 2024—2026-06-07 | 已参与本项目开发或测试观察的历史研究区，不再宣称全新独立检验 |
| 2026-06-08—2026-10-16 | 当前最新任务保留段；仅在确认未用于人工选因子后，冻结少量候选再统一解封；本方案未读取其绩效 |
| 实施方案后尚未发生的交易日 | 按冻结策略做前向模拟，作为新增实证来源；不能回填历史模拟记录冒充实时观察 |

建议历史折的初始参数为：36个月开发窗口，其中末6个月为内层验证，随后6个月为外层检验，步进6个月。样本不足可先做少量折，只作为试运行。不要随机打乱时间做普通K折。

标签若使用 `t+lag` 到 `t+lag+h` 的未来价格，其完整信息区间应在所属开发段内；跨边界样本剔除。必要隔离长度按实际标签重叠和可得时间确定，不机械要求所有60日滚动特征之间都留60日空白。新段可以合法利用之前已发生的历史作为预热。

### 6.3 控制搜索规模，并验证模型的增量价值

单一研究计划建议先固定最多约30个模型候选，例如3轮×10个；加2个人工基线及8个模板作为对照。该数字是限制试错的工程默认值，不是统计显著性的保证。达到预算后先报告结果，不通过就记录失败，不能偷偷换任务继续搜而不计数。

建立同预算对照：

| 组别 | 内容 | 要回答的问题 |
| --- | --- | --- |
| A | 少量简单规则和固定8模板 | 复杂挖掘是否超过简单基准 |
| B | 相同特征、算子、复杂度限制的随机合法表达式 | 改善是否只是搜索次数带来的偶然赢家 |
| C | 模型生成，候选数及计算预算匹配 | 中文假设和反馈是否带来稳定增量 |

三组共享时间切分、交易规则和成本；报告所有候选及失败。评价单位包括净收益、最差窗口、对简单基准的配对差异、重复率、复杂度、耗时和模型用量。比较几个预先固定的随机种子/模型采样，不挑最好的种子汇报。

对模型回放优先保存实际返回内容、实际模型版本与请求参数；温度或随机种子不保证云模型永久生成相同内容。

### 6.4 多重尝试、相关性与稳健性

增加跨任务试验登记，计入表达式、方向反转、阈值、窗口、选约、成本假设及人工修改。54条因子记录不是54个独立假设，28个公式文本也不等于28个独立策略。

去重至少分三层：AST结构、因子值相关性、最终仓位/净收益相似度。固定模板、人工基线和同研究计划历史候选均进入比较。可以保留近似版本做消融实验，但不要把它们当成独立策略分散风险。

优先补充滚动区间表现、完整交易次数、敞口天数、持有期、换手、成本占比、年度贡献、换月附近收益归因及相对基线的增量。时间序列IC应按月份/季度等区间给出稳定性；不能当作多股票截面IC解释。

收益和IC存在时间依赖，应采用适合时间序列的区块自助法或稳健误差估计，并说明区块长度敏感性。进一步引入DSR评估多重选择与非正态收益下的夏普可信度；它不是盈利概率。保存完整候选收益矩阵后再考虑PBO诊断；它也不能替代时间前推和最终锁箱。试验相关性、样本不足及自相关仍需单独处理。[DSR原始论文](https://www.davidhbailey.com/dhbpapers/deflated-sharpe.pdf)、[PBO原始论文](https://www.davidhbailey.com/dhbpapers/backtest-prob.pdf)。

### 6.5 特征扩展的先后顺序

先修语义和检验，再增加信息维度：

1. **已有27项的统一字典。** 记录单位、原始/标准分/标志类型、历史窗口、可得时间、依赖字段、允许角色。由同一字典生成模型提示词、中文释义和界面，修复当前释义不一致。
2. **少量原始方向与非负门控。** 对现有模板做预先约定的消融，比较“方向+强度”与全部标准化方案，保留简单、有增量的版本。
3. **期限结构。** 补足当时全部合格月份，按固定期限/流动性规则选择近远月；示例 `log(F_near/F_far) / ((T_far-T_near)/365)`，正值表示近月较贵，不能直接等同下一期可获收益。设最小期限差，保留同一时点报价。
4. **持仓迁移与结构。** 在完整合约池上计算近远月持仓占比和变化；不把合约迁移描述为单向资金流。
5. **库存/仓单。** 先核实发布时间、频率、修订和季节性；只允许从已发布时点向后使用，并保存数据年龄。不能按统计期起点提前填入。
6. **跨市场与宏观。** 最后考虑LME、汇率及宏观；解决时区、交易时间、合约规格与数据版本后再接入。

不同到期铜合约价格高度相关，把多个合约行直接当大量独立样本容易虚增置信度；月合约面板研究需按日期分组切分和计算不确定性。

## 7. 回测可信度的具体改进

### 7.1 固定订单时序和成交假设

保持“决策、订单、成交、结算”四个阶段的记录：

```text
已发布数据 → 决策时间/目标数量 → 订单提交 → 可成交时点/成交结果 → 盘后结算
```

第一版仍可用日线，但须选择一种明确模式：

- 预提交开盘订单：数量由提交前信息确定；开盘价只用于撮合及预先定义的成交限制，不能看见开盘价格后精确重算数量，再假设仍成交于同一个开盘。
- 开盘后调整订单：可以用已经出现的开盘信息，但成交应落在更晚时点；需要分钟或逐笔样本校验，不能继续无条件沿用开盘价。

保证金风控可使用当时已知的账户与有效规则，但要明确其触发和成交先后。已有“盘后总成交量不影响当日开盘订单”修正要保留；未来增加成交量上限时不能再把当日总量用于预先定单。

### 7.2 成本、流动性和账本

- 成本明确区分交易所/期货公司、比例/元每手、开平仓及适用日期；未知历史费率使用显式情景，不伪装成真实历史成本。平今规则要按完整交易日含夜盘识别。
- 预先约定基础、1.5倍及2倍成本情景，滑点例如1/2/3个最小价位，并考虑更不利成交延迟；这些是压力参数，不是保证可成交的估计。
- 用此前已知成交量和可验证盘口约束研究容量；日线只能给出粗略边界。极端涨跌停、无法换月、保证金上调和交割退出需要连续多日测试。
- 在计入预计手续费、滑点及保证金变化后再次检查资金约束，避免入场时刚好满预算、扣费即超限。
- 每日账本同时保留目标合约与实际持仓、订单时间、可用数据版本、拒单原因、换月两腿费用、持仓和现金变化。
- 分段独立回测目前会重置初始资金/持仓。滚动拼接时明确采用连续账户还是独立折；不能把多个重置账户的收益无说明拼成可执行净值。
- 当前期末按结算盯市，不强制平仓。增加期末持仓展示及可选清算情景，并计入退出费用；不得在报告里把未退出持仓当完整交易。

建议增加一份独立的小型账本核算器，用人工构造的10～20天行情逐笔对账，再抽取真实月份验证。无需立即换成大型回测框架；第二引擎只有在交易规则完全对齐后才有交叉验证意义。

### 7.3 预测标签和策略评价分开

保留目前一日同合约可执行价格标签作为基础预测检验，新增预先固定的1/5/10交易日标签用于研究不同信号速度。多周期标签是新的研究选择，应计入试验计划并处理重叠。

用明确的执行资格标记解释交割、涨跌停及缺参数样本，不用事后交易结果挑选有利IC样本。分别展示“所有合格观测的预测相关性”和“按冻结交易规则实现的净收益”，不能用一项替代另一项。

以下为建议的后续文件/结构，不是本次已创建内容。

| 层次 | 建议位置 | 职责与边界 |
| --- | --- | --- |
| 数据 | `data/quality.py` | 质量规则、官方文件对账、差异分级 |

| 回测 | 现有 `backtest/futures.py`，必要时拆出 `execution.py` | 信号、订单、撮合、账本各自有明确输入 |

Parquet继续用于冻结快照、曲线和实验明细；SQLite作为可查询索引和原始行情库。两者各有用途，不必为“所有内容在一个数据库”而重写现有文件。

具体工程要求：

- 快照/曲线新增文件内容SHA256，读取验证；曲线身份包含算法实现摘要，避免仅靠手工版本字符串。
- 实验包保存依赖锁摘要、Python/包版本、完整代码版本或补丁、提示词版本、输入哈希与数据可用性假设。依赖锁文件已存在，应纳入执行规范。
- 特征和标签可按快照、曲线、版本、截止日缓存；训练与测试缓存隔离，不能用全样本统计缓存回填开发区。
- 数据库使用一致性备份，文件备份同时保存清单；定期恢复演练，不能在WAL活跃时仅复制主 `.sqlite` 文件便认为完整备份。
- 单执行器继续保留。只有明确出现性能瓶颈再引入并发；模型API预算和数据限频仍统一管理。
- 将旧股票CLI明确标为旧入口，文档统一推荐 `cu-research` 与当前工作台，避免误用不同回测实现。

工作量按一名熟悉当前项目的开发者估计，包含针对性测试；不包含等待供应商确认、账号权限和真实前向观察。下面是排期参考，不是交付承诺。

| 阶段 | 建议工作量 | 交付内容 | 验收条件 |
| --- | --- | --- | --- |

## 10. 准入标准与停止条件

### 10.1 先区分工程通过和研究通过

**工程通过**要求：关键数据规则通过、代码和环境可重放、因果测试及边界测试通过、账本可核对、日志和异常有记录。工程通过不附带收益要求。

**研究候选进入前向模拟**建议在计划里预先约定以下标准，执行后不得按结果改门槛：

- 历史前推至少覆盖多个完整外层区间，例如4个以上；这只是最低流程要求，样本置信度仍按有效样本评估。
- 扣除基础成本后整体有正向证据，并相对简单基准有可解释增量；1.5倍成本下不出现明显失效。
- 相邻参数下表现不依赖孤立最优点；改变换月规则或轻微延迟不使结论完全反转。
- 报告最差区间与回撤，不由少数异常日期或换月价差支撑主要收益。可先将单季度贡献超过总正收益50%作为复核提示，而非无条件淘汰规则。
- 交易次数和活跃天数足以支撑区间估计；例如完整往返交易不足30次可标记证据不足，不能把30次当统计充分的保证。
- 独立保留区通过预先约定的检查；已经观察的区间只作重测证据。
- 每条候选有明确成立机制、失效条件、数据假设和仓位解释。

最终只选少量低相关候选进入模拟，例如1～3条。组合权重和选择过程也属于研究试验，不应在锁箱区反复优化。

### 10.2 何时停止加码

出现以下情况应收缩研究，而不是增加模型调用：

1. 模型组在同预算下长期不优于固定规则或随机合法搜索：保留模型做解释与研究辅助，减少自动搜索。
2. 因子仅在单段、单参数或最低成本下有效：标记淘汰，不用更复杂公式掩盖不稳定。
3. 无法确认关键价格和选约时点：不升级为可交易结论，先完成数据审计。
4. 多次使用同一保留区选方案：将其转为开发区，等待新的前向数据。
5. 收益主要来自换月、近交割或低流动性异常：优先复核数据与执行，不将其直接解释为市场机会。
