# 数据拉取与处理、因子挖掘：关键改进方案

日期：2026-10-19。本文基于上一轮代码核查精简整理，仅提出改进方案，不修改功能代码。P0优先解决，P1随后实施。

## 一、数据拉取与处理

现有增量下载、限流重试、请求拆分、缺口记录、SQLite存储和冻结快照继续使用。重点补齐“下载后是否可靠、当时是否可用”。

| 优先级 | 关键问题 | 具体改进方案 |
| --- | --- | --- |
| P0 | **质量检查不完整。** 成交量/持仓缺失、部分无穷值可能漏检；先去重会隐藏同键不同值。 | 入库前检查必需字段、有限值、日期、OHLC关系、非负量持仓及重复冲突；入库后核对主力映射与真实合约行情、换月前日新旧价格。缺失按用途分级，关键错误阻断，可选字段缺失禁用相关特征。 |
| P0 | **交易日期不等于信息可用时间。** 主力映射等缺少历史发布时间与修订证据，滞后2日不能替代核实。 | 记录发布时间、允许使用时间、下载时间及来源版本；未知发布时间明确标记保守假设。特征只读取决策时已可用的数据，历史修订保留版本，核对夜盘交易日归属。 |
| P1 | **缺少独立来源对账。** 接口返回成功只能说明下载完成。 | 首批导入上期所官方文件，抽查30～50个交易日，覆盖普通日、换月、异常波动和节前后。统一单位后逐字段对比，差异写入质量记录并在工作台展示；不得静默用一方覆盖另一方。 |
| P1 | **样本和合约池有限。** 现有研究快照集中于2024—2026；合约池只包含区间内曾成为主力的月份。 | 分批补充更早历史，先保证完整性与统计口径一致。主连研究继续使用当前映射；开展期限结构研究前，另补当时全部符合条件的月份合约，不能把现有池当成完整市场。 |
| P1 | **派生曲线版本仍依赖人工维护。** 改算法漏升版本可能复用旧文件。 | 保留当前因果比例复权和原始月份数据；曲线标识加入算法摘要，文件保存内容哈希。修复数据生成新快照，不覆盖旧实验；追加未来数据后，已生成的历史特征应保持一致。 |

**执行顺序：** 完善质量检查 → 明确信息可用时间 → 官方抽样对账 → 补历史与版本校验。

**验收标准：** 每份快照有质量报告；关键缺口与冲突有明确处理结果；抽查差异可追溯；复权和特征通过历史前缀一致性测试。供应商无法提供历史版本时，报告保留该限制，不能宣称已经完全排除未来信息。

主要改动位置：`data/futures.py`、`data/sqlite.py`、`data/curves.py`；按需要新增小型质量校验模块。

## 二、因子挖掘

现有27项特征、8个固定模板、模型适配和AST白名单继续使用。重点从“生成更多公式”转为“生成可解释、可区分、可验证的候选”。

| 优先级 | 关键问题 | 具体改进方案 |
| --- | --- | --- |
| P0 | **特征解释存在错误。** 当前自动释义仍把原始收益等字段统一称为“标准分”。 | 建立统一特征字典：单位、原始/标准分/标志类型、计算窗口、可用时间及用途；模型提示词、中文解析与界面共用字典。每个因子说明输入、组合逻辑、成立条件和失效风险。 |
| P0 | **验证集反复反馈模型，容易越调越贴合历史。** 目前跨任务的测试区隔离也不足。 | 将模型可见区明确为开发区；按时间滚动开发与独立检验，候选冻结后才进入下一检验段。测试区按品种和日期登记是否已观察，换任务或换快照不能重置；未来收益标签与特征隔离。 |
| P1 | **重复搜索控制不足。** 去重只覆盖单任务的模型候选，未统一比较历史任务、人工基线和模板。 | 建立研究计划，冻结数据范围、特征版本、生成规则和候选预算；先采用约30个模型候选的预算。同计划内跨任务做公式和因子值相关性去重，记录全部尝试、失败及淘汰原因。 |
| P1 | **“有效候选”容易被理解成有效因子。** 当前通过主要表示公式可计算，并不代表预测稳定。 | 状态拆成“可计算、开发筛选通过、独立检验通过”。按时间窗口报告有效样本数、IC/Rank IC、方向一致性和相对基线增量；报告不确定性及全部尝试，不能用单段高分直接晋级。 |
| P1 | **公式多样性不等于信息增量。** 现有特征以量价为主，生命周期也可能被误用为多空方向。 | 明确方向、强度和过滤条件三类用途；到期/换月字段默认用于过滤或分层。先比较模型组合与固定模板、同预算随机合法组合；确认增量后再依次加入期限结构、持仓迁移、仓单/库存。 |

**执行顺序：** 统一特征语义 → 划分开发与独立检验 → 跨任务去重与预算登记 → 分层筛选及基准对照 → 扩展新信息。

**验收标准：** 原始字段不再误称标准分；模型不能访问独立测试反馈；候选和历史模板的重复关系可查；每个因子的状态有依据、中文逻辑与公式一致。独立检验未通过可以得到“本轮无合格因子”的结果，不为凑数量放宽标准。

主要改动位置：`factor/research.py`、`api/models.py`、`research/workflow.py`、`research/presentation.py`；界面增加质量与候选状态展示。

**首轮建议范围：只完成两阶段的P0事项。** 先保证输入可靠、语义正确、研究区间隔离，再扩大下载范围和挖掘数量。
