# 沪铜期货因子组合与特征改造方案

核对日期：2026-10-18。本文是待实施研究方案，不修改特征、候选、数据快照或回测代码，不启动模型挖掘。下列组合均为待检验假设，尚未获得收益验证。

## 1. 结论与当前真实调用路径

**需要调整，但不应把所有股票技术指标推倒重写。** 收益、趋势、波动率、振幅等数学特征可以用于期货；必须改的是价格连续性、合约生命周期、量持仓统计、成交和资金核算，以及信息可得时点。期货专属信息应逐步加入。

首先纠正一个代码定位：当前沪铜工作台的特征来源已经不是 `src/alphagpt/data/features.py`。

```mermaid
flowchart LR
  UI[工作台因子挖掘] --> W[research/workflow.py]
  W --> F[factor/research.py 的 features]
  F --> X[18个标准化特征]
  X --> L[模型组合表达式]
  L --> A[白名单表达式校验]
  A --> B[真实月份合约回测]
```

| 文件 | 当前定位 | 本方案建议 |
| --- | --- | --- |
| `src/alphagpt/data/features.py` | 旧版通用技术特征工程，围绕 OHLC、volume，含大量均线、收益、震荡指标 | 保留旧入口兼容；不直接整体移入沪铜工作台 |
| `src/alphagpt/factor/research.py` | 当前沪铜特征、表达式白名单、中文解释和人工基线 | 作为本次期货特征改造的主要入口 |
| `src/alphagpt/research/workflow.py` | 选择可用特征，组织生成、去重、评估 | 增加特征版本、候选家族、使用范围约束 |
| `src/alphagpt/api/models.py` | 给模型提供特征释义和历史反馈 | 加入期货专属语义、方向与门控约束 |
| `src/alphagpt/backtest/futures.py` | 真实月合约成交、换月、保证金、费用与标签 | 保持信号价格和实际盈亏分离，扩展时继续验证 |

模型当前主要是在预定义特征及运算符中寻找组合，不能自行获取库存、构造新滚动窗口或发明新数据。因此，提高研究空间质量，优先于单纯增加挖掘轮数。

## 2. 股票式实现中哪些保留、哪些调整

| 原有思路 | 判断 | 期货处理方式 |
| --- | --- | --- |
| 多周期收益、均线偏离、突破 | 可保留 | 用因果连续信号价格；不要计算未复权主连的换月跳空收益 |
| RSI、MACD、布林带等 | 可借鉴，暂不全部增加 | 与收益、趋势高度重叠，先选少量代表特征，避免候选数量膨胀 |
| ATR、收益波动率、振幅 | 可保留 | ATR跨日参考必须使用一致的合约/价格口径，不能混入换月价差 |
| 成交量放大、量价关系 | 必须适配 | 真实合约内算历史基准，再按当日映射取值；合约迁移与到期效应另作检查 |
| 持仓量及变化 | 应优先补强 | 区分绝对增减、相对历史偏离和不同期限间迁移；持仓增加不等于多头资金净流入 |
| MFI、“资金流入”类解释 | 谨慎使用 | 成交价乘成交量是成交活跃度代理，不是可识别的资金净流入 |
| 开盘缺口 | 必须重定义 | 同一真实月合约的开盘/前收盘；夜盘遵循交易日归属，不能直接称为自然日隔夜跳空 |
| 股本、市值、股票换手率、公司财报 | 不直接迁移 | 合约持仓与成交量不能替代流通股本；不把成交/持仓比命名为股票换手率 |
| 全局补0、前向填充所有字段 | 需要避免 | 区分预热缺失、供应商缺数和真实零值；行情、参数缺口不能靠填0伪造 |
| 固定涨跌幅截断 | 必须审查 | 不能无说明沿用旧股票阈值；按品种、时期、数据异常与稳健化目的分别处理 |
| 一组特征反复套很多窗口 | 暂缓 | 第一阶段用少量窗口和少量家族；增加近重复项会提高筛选过拟合风险 |

旧 `features.py` 在多处使用 `min_periods=1`、`.fillna(0)`，末尾还有全表 `ffill().fillna(0)`；标准化窗口也包含当前值。这些不等于每个计算都有未来泄漏，但不能直接当作当前沪铜严格预热、历史统计和缺失处理规则的替代品。

期货的保证金、杠杆、换月成本主要属于风险控制和回测核算，不应全部塞进“预测涨跌”的表达式。先区分预测信号、执行条件、仓位缩放三个层次。

## 3. 当前已经具备的期货适配与边界

当前 `factor/research.py` 已经：

1. 按真实月份合约分别计算量与持仓历史基准，再映射到主力序列。
2. 换月时使用前一交易日新旧合约收盘价进行比例衔接，追加未来数据不重写历史信号。
3. 量持仓变化基准在2020年前后按统计口径分段预热。
4. 特征保留预热缺失，不使用全量补0制造有效样本。
5. 特征标准化用之前的滚动统计，模型只能通过白名单表达式组合。
6. 回测按真实月合约成交和盯市，默认决策延迟2个交易日，不把连续信号价格当真实成交价。

这些处理值得保留，但仍存在需要研究的边界：同一合约的量持仓也受距到期时间影响；历史主力映射的精确可得时刻未逐条证实；仅有曾经成为主力的月份合约，不构成完整期限曲线；当前18项主要是量价技术特征。

## 4. 现有18项特征字典

以下“原始含义”是标准化前的含义。**模型实际拿到的18列均为标准分，而不是原始数值。**

| 特征名 | 原始含义 | 研究角色与主要限制 |
| --- | --- | --- |
| `ret5` | 连续信号价格5日收益 | 短期方向强弱；标准分的正号不是原始收益必然为正 |
| `ret20` | 连续信号价格20日收益 | 中期方向强弱 |
| `ret60` | 连续信号价格60日收益 | 较慢趋势背景，预热较长 |
| `trend20` | 连续收盘相对20日均线偏离 | 中期偏离程度；标准分零点不是价格穿越均线 |
| `trend60` | 连续收盘相对60日均线偏离 | 慢趋势背景 |
| `reversal` | 负的连续3日收益 | 相对近期的反转压力，不能机械解释为下跌必反弹 |
| `volatility` | 连续日收益20日标准差 | 风险/环境变量；标准化后可为负 |
| `volatility_ratio` | 5日波动率/20日波动率−1 | 波动加速背景；标准分正号不是原始比值必然大于1 |
| `range20` | 月合约日内振幅比例的20日均值 | 风险背景；各日比例使用当日原始OHLC |
| `close_position` | (收盘−最低)/(最高−最低)−0.5 | 日内收盘位置；标准化后0不等于区间中点 |
| `volume_ratio` | 当前合约成交量/此前20日均量−1 | 相对活跃度；临近交割及主力迁移会干扰 |
| `oi_change5` | 当前合约5日持仓变化率 | 交易参与变化；标准分为正不保证原始持仓在增加 |
| `oi_ratio` | 当前合约持仓/此前20日均持仓−1 | 持仓相对历史水平 |
| `volume_oi` | 当日成交量/持仓量 | 交易频繁程度，不提供多空方向 |
| `price_volume` | 1日连续收益 × 原始成交量偏离 | 预先计算后再标准化的交互项 |
| `price_oi` | 5日连续收益 × 原始5日持仓变化率 | 双负也可为正；不能直接称为“多头增仓” |
| `breakout` | 收盘相对此前20日高低价区间中点的偏离 | 不是严格“突破前高”布尔信号 |
| `vol_change` | 20日收益波动率的5日差值 | 风险扩张程度，无天然多空方向 |

### 4.1 标准分是第一阶段必须讲清楚的问题

当前计算口径可写为：

```text
Z_t(x) = [x_t − mean(x_(t-60), …, x_(t-1))]
         / std(x_(t-60), …, x_(t-1))
至少30个历史有效观测，分母为0则缺失。
```

例如：历史20日收益均值为−5%，当天20日收益为−1%，收益标准分仍可能为正。故 `sign(ret20)` 表示“高于/低于历史平均的收益”，不是“上涨/下跌”。同理，持仓变化率由−10%改善到−2%，其标准分也可能为正，但仍然是减仓。

**方案：本阶段保留现有口径用于可比较的组合实验；下一阶段同时提供原始方向变量和标准分强度变量，并在特征名称中明确区分。** 不能改同名字段含义后继续复用旧实验。

`Z(raw_return × raw_oi_change)` 也不等于 `Z(raw_return) × Z(raw_oi_change)`。模型解释必须对应实际计算顺序。

## 5. 第一阶段：现有数据即可验证的8个组合

目标：先比较少量有明确逻辑的组合，不增加数据接口，不把公式多样性当成经济逻辑多样性。

以下公式可以由当前表达式白名单解析；输入均为上表标准分。`tanh` 将输入压缩到−1至1之间，减少极端值影响。初始 `expected_direction` 全部事前设为 `1`，只是明确研究假设；不允许用最终测试区挑正负方向。最终仓位仍经过现有信号标准化和阈值规则，不是直接把公式输出当手数。

### F01 多周期相对动量

```text
0.6 * tanh(ret20) + 0.4 * tanh(ret60)
```

中文逻辑：把中期与慢速收益相对各自历史水平的偏离合并，假设两者同时增强时，后续可交易收益更倾向延续。较慢项降低只追逐短期噪声的程度。这里衡量的是相对历史的动量增强，不保证原始收益已经转正。适合趋势持续的研究场景，快速反转、方向频繁切换和换月处理错误时容易失效。0.6与0.4为初始约定，不代表最优权重。

### F02 活跃度增强的区间偏离

```text
 tanh(breakout) * (1 + 0.5 * tanh(volume_ratio))
```

中文逻辑：用价格相对历史区间中点的偏离变化提供方向，再用成交活跃程度调节强弱。括号始终为正，范围约0.5至1.5，因此成交缩量只削弱信号，不会把原方向自动翻转。这不是“突破前高且放量”的严格事件定义。假突破、交割前成交结构变化和主力迁移可能让活跃度信号失真。

### F03 持仓参与增强的相对动量

```text
 tanh(ret20) * (1 + 0.5 * tanh(oi_change5))
```

中文逻辑：研究持仓变化相对自身历史更强时，中期相对动量是否更容易延续。正值门控保持动量方向，但并不把持仓解释为买入资金：一份新增持仓同时对应多空双方，也可能只是减仓幅度收窄。该组合需要与不带持仓项的动量基线比较，检查是否只是合约生命周期的代理。

### F04 量持仓共同确认

```text
 tanh(ret20) * (1 + 0.25 * tanh(volume_ratio) + 0.25 * tanh(oi_change5))
```

中文逻辑：在相同动量方向上，用成交活跃度和持仓变化两种不同参与信息共同调整强度，避免任何一个量持仓指标决定全部方向。权重门控仍为正。若两项高度相关，它可能只是F03的近重复版本；若增量验证价值不足或换月附近收益异常集中，应淘汰，而不是因为公式更复杂而保留。

### F05 波动环境约束的短期反转

```text
 tanh(reversal) / (1 + 0.5 * (1 + tanh(volatility)))
```

中文逻辑：研究短期价格偏离后是否存在修复，同时在波动率相对历史偏高时减弱信号，避免在剧烈单边行情中持续逆势。分母约为1至2，始终正且不接近0。它降低的是高相对波动时的反转强度，不表示低波动环境一定安全；趋势加速与手续费滑点可能吞噬收益。

### F06 日内位置约束的反转

```text
0.7 * tanh(reversal) - 0.3 * tanh(close_position)
```

中文逻辑：将短期相对反转压力与当日收盘位置的异常结合，假设近期弱势且收盘位置相对历史偏低时，随后更可能出现价格修复。这个假设可能与价格延续相反，因此适合作为明确的反转家族候选，而不是混入趋势叙述。连续跌势、消息冲击和涨跌停环境容易失效；标准分低不必然代表收在当日最低附近。

### F07 波动加速折减的慢趋势

```text
 tanh(trend60) / (1 + 0.5 * (1 + tanh(volatility_ratio)))
```

中文逻辑：保留慢趋势相对历史偏离的方向，当短期相对长期波动出现异常扩张时降低强度，研究其能否缓解追涨杀跌后的回撤。它是环境调节，不是完整的目标波动率仓位管理；波动扩张也可能恰好是趋势启动阶段，折减会错失行情，必须检查收益与回撤的实际权衡。

### F08 高频换手与波动扩张共同折减

```text
 tanh(ret20) / (1 + 0.25 * (1 + tanh(volume_oi)) * (1 + tanh(vol_change)))
```

中文逻辑：当成交/持仓比和波动变化同时相对历史偏高时，假设行情噪声、短线博弈或交易成本风险升高，因而削弱相对动量。两项只作为风险背景，不解释为资金净流出；分母约为1至2。趋势启动时也可能出现同样状态，故该组合的价值必须来自样本外成本与回撤改善，不能只看拟合期夏普。

### 5.1 组合使用方式

- 先分别评估8个单因子，不立即把8个一起加权。
- 与现有人工基线、F01相对动量基线比较，确认新增门控的增量价值。
- F01/F02/F03/F04/F07/F08主要属于趋势及趋势调节家族，不能当作6种独立风险来源。F05/F06属于反转家族。
- 同一家族先保留最简单、成本后表现稳定的代表项；不预设“必须选满几个”。
- 只有单因子通过后，再在开发区评估少数代表项的等权组合；不要先为所有项优化一大组权重。
- 风险缩放应留在执行层：对实际波动估计、目标风险、保证金和持仓上限做独立控制，不把负的波动标准分当杠杆。

## 6. 第二阶段：补强期货专属特征

### 6.1 优先级P0：原始方向、合约内行为和生命周期

| 拟新增变量 | 定义建议 | 数据需求与用途 |
| --- | --- | --- |
| `ret20_raw`、`ret60_raw` | 因果连续价格原始收益；名称与标准分区别 | 现有数据可算，保留实际正负方向 |
| `oi_change5_raw` | 同一真实月合约5日持仓变化率 | 现有数据可算，保留真实增减仓符号 |
| `close_location_raw` | (C−L)/(H−L)−0.5 | 现有数据可算，保留真实收盘区间位置 |
| `days_to_last_trade` | 最后交易日−当前交易日的日历天数 | 合约资料可算，优先作为执行/样本分层条件，不强制标准化 |
| `days_since_roll` | 根据截至当日已知映射计算距最近切换的交易日数 | 用于换月敏感性诊断；不得使用“距离未来下一次主力切换还有几天” |
| `same_contract_ret5` | 当前真实合约自身的5日收益 | 与其自身OI变化配对，减少连续收益与另一合约行为混合 |
| `turnover_proxy_z` | 成交/持仓比的历史标准分 | 作为活跃/拥挤代理，不解释为流通股换手率 |

未来真正要表达“上涨增仓”时，应基于同合约原始收益和原始OI变化分别判断，而非判断它们标准分的正负；“增仓上涨/增仓下跌/减仓上涨/减仓下跌”是描述性分组，不证明交易者动机。

特征注册应记录 `raw` / `zscore` / `bounded` / `flag` 类型，提示词和公式释义分别处理。当前函数默认把所有列标准化，因此这些原始/标记变量不是只改一个字段名就能接入，属于下一阶段明确的代码改造。

### 6.2 优先级P1：期限结构与展期背景

期限结构是期货相对传统股票量价研究的重要增量，建议作为首个新数据方向。现有月份日线可复用，但必须确认近远月同日覆盖，不能把“曾经当过主力”误认为完整合约池。

```text
carry_raw(t) = ln(F_near(t) / F_far(t)) × 365 / [T_far − T_near]
```

- `F` 为同一交易日两份合约未复权、同口径结算价；`T` 使用预先约定的合约最后交易日作为期限代理，单位为日历天。
- 本指标无量纲，按年化比例表示；正值表示所选近月价格高于远月。它是曲线斜率代理，不等于锁定收益或真实换月收益。
- 合约选择规则只用当时已经上市、报价有效、满足流动性条件的合约；临近最后交易日的合约排除或独立研究，阈值在开发前固定。
- 可以研究 `trend_raw × 正值carry门控`、`carry_z + 库存变化项`，但必须先验证单项；不要直接用复权主连价格算近远月价差。
- 相邻期限、固定期限插值、主次主力选择是不同定义，第一版只选一个明确规则，避免事后挑选最有利曲线。
- 需要补充近远月合约的同步覆盖；缺一腿则缺失，不前向填入已过期报价。

### 6.3 优先级P2：仓单、库存及季节性

| 因子方向 | 初始定义建议 | 时间与数据约束 |
| --- | --- | --- |
| 仓单变化 | 商品总仓单的5/20日变化或历史标准分 | 使用 `fut_wsr`；核对单位、明细与合计层级，不能重复相加 |
| 库存变化 | 最近已公布库存相对上期变化 | 周频按实际公布时点进入日频；不能提前回填到统计周起点 |
| 库存季节性偏离 | 与此前历年同季节统计比较 | 仅用当时已知历史；样本年数不足则暂缓 |
| 曲线×库存 | 期限结构和库存变化的交互 | 可得日期统一，分别检验单项及增量价值 |

仓单量不等于全社会库存；仓单注销、注册、仓库规则和交割安排都可能改变其含义。中文解释只能提出供需假设，不能把仓单减少直接写成需求增加。

### 6.4 后续再考虑的方向

现货基差、进口盈亏、汇率、海外铜价与宏观数据可以扩展，但涉及品级、税费、币种、交易时区、公布修订与数据权限。它们不进入第一版MVP；也不能把当前快照没有的数据作为模型已知输入。

## 7. 候选生成约束

第一阶段建议：8个固定模板先验证；模型再按家族提出少量变体，每轮不超过当前默认10个候选，先1轮，保留所有失败与淘汰记录。

1. 每个组合最多2至4个基础特征；限制无经济解释的深层嵌套。
2. 初始窗口沿用现有5/20/60日及历史标准化规则，不让模型发明窗口或未来位移。
3. 单候选只提出一个主要经济假设，清楚区分方向、强度与风险门控。
4. 强度门控使用严格正且有界的表达式；要允许方向翻转时必须明确解释，不能无意由负标准分触发。
5. 避免除以近0量、价格差或标准分；不用随意小常数掩盖不稳定分母。
6. 中文逻辑必须包含字段口径、计算顺序、预期方向、适用情景和失效条件。
7. 标记 `family`、`feature_version`、`data_snapshot`、`expected_direction` 和生成父因子；这些为拟新增研究元数据，不代表当前都已实现。
8. 当前全局相关性限制不是充分的去冗余机制。家族内还应看开发区因子值与仓位相关性、回测重叠程度；阈值需预先约定，不用最终测试集选阈值。

## 8. 验证与验收方案

### 8.1 先验数据与计算正确性

- 检查主力映射、必要月合约OHLC、涨跌停参数与实际交易覆盖；新旧合约衔接所需前日价格必须存在。
- 追加或修改未来数据不改变历史特征；逐日前缀计算与全量计算的同日结果一致。
- 合约内量持仓基准不跨合约；统计口径变化及预热缺失处理一致。
- 换月两边价格存在较大基差时，不得凭拼接制造趋势或回测盈利。
- 同合约价格不变且仅交易合约切换的可手算案例，应只有约定费用和滑点损耗。
- 结算参数缺失不填0；固定成本可研究，历史手续费模式按实际成交日严格检查。库存、carry缺失也不能伪装中性值。

### 8.2 研究时间与执行口径

沿用已讨论的初始划分：2020—2023训练、2024验证、2025—2026年9月作为候选保留测试区，**前提是该段未参与模型反馈、筛选或人工调参**。若已使用，就标记为开发数据，另留未来区间。不能因为修改特征版本就重新宣称已看过的测试区未见。

当前已有的2025—2026快照不能覆盖2020—2023训练，正式研究前仍需补齐训练数据及预热。下载过不等于已经参与筛选，也不等于数据已经完成独立交叉核验。

当前默认执行延迟2个交易日，现有执行标签偏向短期可交易收益；20/60日特征不自动意味着20/60日持有策略。若研究更长预测期，应独立扩展标签、持有和调仓规则，并重新做分段末端截断，不能只换一个指标名称。预热长度按最长特征回看与标准化窗口的叠加需求确认。

### 8.3 选因子不只看夏普

| 检查维度 | 应回答的问题 |
| --- | --- |
| 单项增量 | 相比简单动量/反转基线，多加的OI、量或波动项是否有贡献？ |
| 稳定性 | 不同年份、趋势/震荡、换月附近是否表现方向一致或有可解释差异？ |
| 成本 | 正常成本及预先约定的较高成本下，是否仍有研究价值？ |
| 集中度 | 是否只靠少数天、一个合约或单次换月获利？ |
| 参数敏感性 | 相邻少量参数是否合理，不是孤立尖峰？ |
| 重复性 | 多个公式是否只是同一个仓位序列的不同写法？ |
| 可交易性 | 涨跌停、到期退出、保证金约束和换月成交后结论是否成立？ |
| 多重尝试 | 全部候选、调用次数、家族及淘汰原因是否保留？ |

不预设保证获利的夏普门槛，不在单一沪铜上把几千个相关表达式当成独立发现。最终组合优先简单、稳定、低冗余，而非训练期最优。

## 9. 推荐实施顺序

| 阶段 | 交付 | 范围 |
| --- | --- | --- |
| 第一步：口径冻结 | 现有18项字典、版本号、8个模板与逻辑 | 不增加数据接口；先校验表达式与历史因果性 |
| 第二步：模板验证 | 各模板与人工基线的开发区对照报告 | 数据补齐后验证，保留训练/验证/测试边界 |
| 第三步：方向与生命周期 | 原始方向变量、合约内收益、类型化特征注册 | 优先解决标准分语义和迁移效应，不堆技术指标 |
| 第四步：期限结构 | 近远月覆盖、carry定义及版本化快照 | 作为首个期货专属新增信息方向 |
| 第五步：库存仓单 | 可得时点、单位、去重与缺口规则 | 数据通过核验后加入少量供需组合 |

建议先实施前两步，再根据结果决定扩展。不要直接把旧100多个技术特征、期限结构和库存一次性全接入。
