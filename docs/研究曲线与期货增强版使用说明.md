# 研究曲线与期货增强版使用说明

实施日期：2026-10-19（北京时间）。本轮落实曲线选择、独立因果复权主连、方案8个组合和现有数据可支持的期货特征增强。近远月、仓单和库存仍属后续数据接入阶段，不伪造未接入字段。

## 1. 挖掘曲线选择

在“因子挖掘 → 研究数据快照”之后新增：

- **因果比例复权主连（推荐）**：按主力映射取真实月份行情，因果衔接OHLC，适合价格趋势/反转特征。
- **原始未复权主连**：只作换月污染对照，不将其跳空作为可交易收益。
- **真实月份合约原价**：固定合约，不换月；界面按该合约与快照的交集限制研究日期，预热或开发样本不足时拒绝挖掘。

所有选项均在真实月份合约原价上回测，复权价格不是成交价。快照、曲线、处理方式、特征版本和模板开关随任务冻结；旧任务不会自动切换。

点击“生成并登记所选研究曲线”可查看交易日、实际合约、原始收盘、信号收盘、调整系数和换月标志。数据展示页也提供因果复权主连选项，并调用相同算法。

## 2. 复权方法与保存

```text
切换日t：A_t = A_(t-1) × C_旧合约(t-1) / C_新合约(t-1)
非切换日：A_t = A_(t-1)
信号OHLC(t) = 当天映射真实合约OHLC(t) × A_t
```

初始调整系数为1。不使用未来切换日，不用样本末端价差重算历史。新旧前日价格缺失或无效则失败，不补造。量、持仓、成交额保持原值。

- 文件：`runtime/curves/<curve_id>/bars.parquet`，冻结保存原始值、信号值、调整系数、实际合约和生命周期标记。
- 元数据：SQLite `objects` 中 `kind='curves'`；包含快照、代码、处理方式、算法版本、数据截止日和文件路径。没有改动原始行情表。
- 曲线ID由上述身份字段确定；已有文件不原地覆盖。算法或口径改变时必须修改版本。
- 挖掘/开发评估的派生曲线仅包含验证截止日及以前数据；最终测试另按其截止日生成版本，避免先生成未来特征再交给开发过程。
- 全区间展示曲线与开发区曲线因截止日不同，ID可以不同；曲线前缀应完全一致。

DBeaver可查看元数据：

```sql
SELECT id AS 曲线编号,
       json_extract(payload,'$.snapshot') AS 原始快照,
       json_extract(payload,'$.code') AS 曲线代码,
       json_extract(payload,'$.mode') AS 处理方式,
       json_extract(payload,'$.version') AS 算法版本,
       json_extract(payload,'$.asof') AS 截止日期,
       json_extract(payload,'$.path') AS 冻结文件
FROM objects WHERE kind='curves' ORDER BY created DESC;
```

## 3. 特征和组合

新建任务默认 `futures-v2`：保留18项历史标准分，再加入9项明确类型的特征，共27项。

| 新特征 | 类型与解释 |
| --- | --- |
| ret20_raw / ret60_raw | 原始连续价格收益，正负才表示实际涨跌 |
| oi_change5_raw | 同合约原始持仓变化，正负表示增减仓，不代表单边资金流 |
| close_location_raw | 原始日内收盘位置，范围[-0.5,0.5] |
| same_contract_ret5_raw | 同一真实合约5日收益 |
| same_contract_price_oi_raw | 同一合约5日收益与持仓变化交互，不混入另一合约收益 |
| days_to_last_trade | 距已知最后交易日的日历天数 |
| days_since_roll | 距最近已发生切换的交易日数；首次观察到换月前为缺失，不伪造起点 |
| is_roll | 当日映射是否已经切换，0/1 |

原始方向、生命周期和标志不再自动转成标准分。提示词与公式解释明确区分类型；新增候选最多组合4项基础特征，仍受AST白名单约束。

旧任务配置未保存特征版本时自动解释为 `legacy-v1`，继续用18项旧特征；恢复、重测和导出不会悄悄升级算法。历史结果文件不改写。兼容旧特征不等于保留错误的成交时点判断；重测使用当前修正的执行实现并记录代码版本。

“评估方案中的8个固定因子组合”默认启用，在人工基线之外计算F01—F08，不增加模型调用。它们作为方案模板单独列出；模型候选数量不包含模板与人工基线。模板依赖特征不可用或近常数时记录淘汰原因，不用缺失填0，不因此中断整个任务。

8个固定模板保持原方案公式，不宣称已验证盈利；模板的有效候选状态表示满足计算/评估要求，不代表达到盈利标准。期限结构carry、库存/仓单和宏观特征尚未接入。

## 4. 无未来数据约束与修正

1. 特征统计只用当前盘后及历史值，标准化基准向后错开1日；默认信号滞后2个交易日执行，至少滞后1日。
2. 因果复权仅用切换前一交易日新旧价格，不读取未来价差。
3. 模型只得到开发区可用特征说明和训练/验证反馈；开发过程在构造特征前截断到验证截止日，不读取测试区特征。
4. 表达式禁止 `shift`、属性/下标访问、任意函数、`eval`、导入及标签引用；只允许既定列和白名单算子。
5. 预测标签必须引用事后收益才能评价，属于独立离线评分数据，不是特征、模型输入或下单依据。各分段末端截断跨边界标签，最终测试仍须单独解封。
6. **修正原执行逻辑**：删除用“当日总成交量>0”判断当日开盘是否成交的条件。日总量盘后才知道，不能反向决定开盘订单。当前仅用可用开盘报价及约定交易约束模拟撮合。
7. 开盘可成交量、排队和真实盘口仍非日线数据可完整复现；当前是日线开盘撮合假设，不能宣称等同真实成交。精确流动性约束需要当时可得的盘口或成交数据。
8. 当天收盘/结算用于当天结束的盯市与下一可成交时点的风险处理，不用于当天开盘决定；保证金和涨跌停参数按适用交易日作为执行约束，历史精确公布时点和供应商修订仍需额外来源核验。

代码层的因果检查不能替代供应商历史版本和公布时间审计。默认执行滞后是保守假设，不是历史映射点时可得性的完整证明。

## 5. 验收范围

- 合成数据：换月价差、固定月份选择、同合约交互、曲线不可变、历史配置兼容、模板缺项处理、模型/回测/重测/最终测试/导出。
- 无未来回归：多个历史前缀与全量计算一致；改变未来价格、量持仓及映射不改变历史特征和账本；改变当天盘后收盘/结算/总成交量不改变当天开盘订单；表达式越权调用被拒绝。
- 真实冻结数据：两份快照的全区间曲线构建和多个前缀精确对照。
- 真实模型联调：仅使用已参与开发的2024区间，1次模型调用、2个模型候选，加2个人工基线与8个模板，完成开发区回测及导出。未额外解封2025—2026测试区。

验证脚本：`scripts/verify.py`、`scripts/verify_research_curves.py`。运行真实联调前需关闭工作台，避免单执行器锁冲突；会调用配置模型，产生供应商用量。

真实联调报告：`runtime/verification/research_curves_acceptance.json`；命令完整输出：`runtime/verification/research_curves_acceptance_command.log`。任务 `mine_20261019_000749_6c7b4d38` 的完整事件日志位于 `runtime/logs/mine_20261019_000749_6c7b4d38.jsonl`。后续复测报告、最终单测路径在交付时另行记录。
